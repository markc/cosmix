# Contributing as an agent

This file is for an AI agent (or a human driving one) landing its first change
in `markc/cosmix`. It lists the gates a change must pass, not the philosophy —
`CLAUDE.md` and `AGENTS.md` carry that, and `docs/dev/{bus,mix,cos}/` holds
the per-area `AGENTS.md`/`CLAUDE.md` you should read before touching that
area. This file is the checklist.

The measured target: **`git clone … && ./bootstrap && mix man overview` to a
first green test in one session, unattended.** If you can't get there, that is
a bug in this repository — report what tripped you, with the exact command
and output.

## Where things are

- The repository root has no `Cargo.toml`. There are two Cargo workspaces:
  `src/` (Bus, Mix, substrate libraries, daemons — every crate flat under
  `src/crates/`) and `src/desktop/` (compositor, CTK, apps — its own
  toolchain, pinned in `src/desktop/rust-toolchain.toml`). Every `cargo`
  command below runs from one of those two directories.
- `src/crates/cosmix-foreman` is halted and excluded from the workspace
  (`src/Cargo.toml`); its tests are not a gate. Leave it alone.
- `ctl/` is the public *starter* control hub (sanitised docs, plans, specs,
  decisions, scripts). Operators copy it out to a private hub; operator-specific
  material never lands here, sanitised starter material does.
- `docs/` is the cosmix.dev site. `docs/mix/`, `docs/cos/`, `docs/bus/` are the
  manuals' sources. `mix man` serves a fresh cache or the online copy first
  and falls back to `docs/mix` in the tree; `COSMIX_MAN_SOURCE=local` skips
  the network (tree page first, cache if the page is missing).

## The ten gates

1. **First-party scripts are Mix, never Python.** Every script, hook, one-shot
   and piece of glue is Mix (`bin/mix` after `bootstrap`; `/opt/cosmix/bin/mix`
   on a system install). `bootstrap` is the only first-party `sh` script,
   because `mix` does not exist yet when it runs; vendored upstream sources
   keep their own scripts. A missing Mix primitive is a Mix bug: fix it in
   `src/crates/cosmix-lib-mix/`, add the `docs/mix/` page, and bump
   `cosmix-lib-mix` **and** `cosmix-mix` together — they move in lockstep
   (`docs/dev/mix/CLAUDE.md`). `mix man overview`, `mix man syntax`,
   `mix builtins` and `mix -c '<probe>'` are the oracle; probe before you
   assume.

2. **Zero-warning clippy, per workspace.**
   `cd src && cargo clippy --workspace --all-targets -- -D warnings` and
   `cd src/desktop && cargo clippy --workspace --all-targets -- -D warnings`.
   `cargo fmt -p <crate>` on the crates you touched — never a repo-wide
   `cargo fmt` from a task.

3. **Tests at the tree's density, green before you push.**
   `cargo test -p <crate>` for every crate you changed, plus the workspace run
   for anything touching a shared library. **A per-crate gate must name the
   feature set that makes that crate's tests compile, and must assert a
   non-zero test count.** A bare `-p <crate>` on a crate whose tests live
   behind a non-default feature compiles them out and still reports `ok`,
   which reads exactly like coverage. Worked examples:
   `cargo test -p ctk --features bus,theme` — ctk's default is
   `menus, platform-wayland`, so a bare run drops every Bus and theme test;
   and `cargo test -p cosmix-shell --features chrome` — `cosmix-shell` has
   `default = []`, so a bare run reports `0 passed` for `src/lib.rs` while the
   `tests/` files still pass, and the whole thing looks green. Read a crate's
   `[features]` before trusting its run, and if the count is zero say so
   rather than calling it green. A protocol change in `cosmix-comp`
   gets a test in `src/desktop/crates/cosmix-comp/src/protocol/tests.rs` — a
   real Wayland socket and hand-assembled wire bytes, not a mock. Copy the
   shape of the nearest existing test.

4. **Docs in the same commit.** A behaviour change ships with its page under
   `docs/`. Added, renamed or removed a page? Regenerate the HTML shells:
   `mix docs/build/gen-doc-pages.mix`, and commit them. No "docs later".

5. **Bump the crate a consumer would notice.** Each package has its own
   version. New builtin, verb, flag, wire/schema/config format, error
   semantics or observable behaviour → bump (pre-1.0: compatible → PATCH,
   breaking → MINOR). Docs, tests, refactors, formatting → no bump, say so.
   `docs/VERSIONS.md` (generated by `ctl/_bin/gen-versions.mix`) ledgers the
   `src/crates/*` manifests — desktop packages are not in it yet; what a
   deployed node runs is answered by `mix --version` on that node.

6. **The app registry is append-only.** A new desktop app claims a slug in
   `src/desktop/APPS.md` first (`apps/<slug>`, package `cosmix-<slug>`, id
   `dev.cosmix.<slug>`); retired slugs are never reused, and a slug may not
   collide with a daemon stem (`chat`/`chatd` are banned together — `mail`/
   `maild` is the one grandfathered, closed exception).

7. **New GUI apps render through `DcsAppShell`.** Chrome (menu bar, toolbar,
   sidebars, status) goes through `ctk::dcs_app_shell::DcsAppShell`; apps
   inject content into slots and never assemble shell structure. Tower,
   FileMgr and Mail use it; Studio is the documented temporary exception
   (`APPS.md` § Application shell) — don't copy its hand-assembly.

8. **Nothing private, ever.** This tree is public and history is permanent.
   No real host names, WireGuard/LAN addresses, domains, certificates, keys or
   operator home paths — not in code, tests, fixtures, or doc comments.
   Sanitise to RFC 5737 addresses, `example.*` domains and alpha/beta/gamma
   node names. The maintainer's clone runs a hygiene gate as a
   pre-commit/pre-push hook; your clone does not, so the rule is yours to
   keep.

9. **New backend work is event-driven; polling is banned.** A queue-drain or
   job worker is woken by a Bus `*.wake` verb or a subscription, not a clock
   (`ctl/_decisions/2026-07-20-no-poll-event-driven-amp-wake.md`). A
   `while true + sleep` under a minute, or a systemd timer under five minutes,
   does not merge. Two existing daemons (`cosmix-indexd`, `cosmix-musicd`)
   still run 1 Hz snapshot loops — that is debt, not licence. If doing it
   right needs a capability the substrate lacks, add the capability.

10. **Agentic-first: no human ceremony on an agent's path.** A confirmation
    prompt, typed nonce or interactive approval on a path an agent must drive
    is a design bug (`ctl/_decisions/2026-08-16-agentic-first-security-is-opt-in.md`);
    ship the unattended path as the default and the guard as an opt-in flag.
    Correctness invariants (device/VT identity, TOCTOU re-checks, resource
    ledgers) stay unconditional — the test is "does this gate stop an agent
    doing something *wrong*, or only make a human vouch?"

Plus the two habits every review here asks for: **verify your own claim**
(re-run the gate, read the load-bearing diff — a green summary is not
evidence) and **converge** (a review finding is fixed, or declined with a
reason; nothing ships half-fixed).

## Good first tasks

Bounded, upstream code exists, the harness needs no structural change, and
you can verify the result yourself. All three are in `cosmix-comp`
(`src/desktop/crates/cosmix-comp`), delegating a protocol Smithay already
implements (vendored under `src/desktop/vendor/smithay/src/wayland/`).

| Task | Smithay module | Size | What "done" looks like |
|---|---|---|---|
| `ext-idle-notify-v1` | `idle_notify/` | days | global advertised; a notification fires after N ms without seat input and resumes on input; a `tests.rs` case drives it over the socket |
| `ext-foreign-toplevel-list-v1` | `foreign_toplevel_list/` | days–1 wk | every mapped toplevel is announced with a stable identifier, title/app-id updates propagate, close is reflected; harness case |
| `ext-session-lock-v1` | `session_lock/` | 1–2 wk | one lock surface per output, above every other surface, keyboard focus latched until unlock; harness case. Needs a new surface role — read `protocol/handlers.rs` around the xdg configure gate first |

Pattern for all three: register the global beside the others in
`protocol/mod.rs`, `delegate_*!` in `protocol/handlers.rs`, add the harness
test (bind the global in `registry_globals`, follow an existing map test),
PATCH-bump `cosmix-comp`, document the protocol in `docs/cos/`. Only
session-lock extends `SurfaceRole` and the configure machinery; the other
two create no surfaces.

## Your first session, measured

Prerequisites: `git`, a rustup-compatible `cargo` (bootstrap fetches one if
absent, via `curl`), `pkg-config` and the usual native build libraries
(ALSA, etc.), and the time and disk for a full release build — `bootstrap`
builds `mix`, writes `env`, then runs `setup.mix`, which release-builds the
whole `src/` workspace and installs its binaries to `bin/`.

```sh
git clone https://github.com/markc/cosmix && cd cosmix
./bootstrap                              # mix → bin/, env, then the workspace
. ./env && mix man overview              # the mental model
cd src && cargo test -p cosmix-lib-mix   # first green test
```

Time it. Any step that needs a human or a guess is an issue: file it with
the step and the output. The one-session target is the gate this file is
measured by.
