# CosMix plasmoid deployment contract

The control-repo deployer owns deployment. This project only defines the build,
stage and validation contract; do not add it to the Cargo workspace.

## Build and test

Run from the `cos` repository root:

```sh
cmake -S desktop/apps/plasmoid \
  -B desktop/apps/plasmoid/build-release \
  -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_TESTING=ON \
  -DCMAKE_INSTALL_PREFIX=/usr/local
cmake --build desktop/apps/plasmoid/build-release
ctest --test-dir desktop/apps/plasmoid/build-release --output-on-failure
```

## Stage

Use a fresh deployer-owned staging directory:

```sh
DESTDIR="$stage_root" \
  cmake --install desktop/apps/plasmoid/build-release
package_root="$stage_root/usr/local/share/plasma/plasmoids/dev.cosmix.plasmoid"
find "$package_root" \
  -type f -printf '%P\n' | sort
desktop/apps/plasmoid/build-release/bin/staged_backend_probe "$package_root"
find "$package_root/contents" -name '*.qml' -print0 \
  | sort -z \
  | xargs -0 /usr/lib/qt6/bin/qmllint \
      -I desktop/apps/plasmoid/build-release/bin
```

`$stage_root` must be an explicit fresh temporary directory created by the
deployer. It must not be `/`, `$HOME` or the source tree.


The generated names are validated against the actual staged tree at build time.
The deployer must fail closed if files land outside the single plasmoid package
root or if the staged ledger differs. `staged_backend_probe` is also a hard
gate. It reads the staged `main.qml`, requires the package-relative
`import "CosmixBackend" as CosmixBackend`, verifies the enabled desktop
`SystemServices` notification-area metadata and active Plasmoid status, and
uses a fresh `QQmlEngine` to instantiate `TraydBridge` through the staged
`qmldir`. Its import paths exclude the build-tree module, so success proves the
package-local plugin and backing library load without a global QML install.

Run `qmllint` against the staged package, not the source package. The
package-relative backend directory is generated by CMake and does not exist
beside source `main.qml`.

## Install and validate

The deployer installs the verified staged ledger file-by-file into the matching
live package root. It must union these paths into its managed manifest and must
never delete, mirror, or infer stale paths from the package directory:

```sh
install -d /usr/local/share/plasma/plasmoids/dev.cosmix.plasmoid
# For each regular file in the exact 19-file ledger above:
install -D -m "$staged_mode" \
  "$stage_root/$ledger_path" "/$ledger_path"
kpackagetool6 --type Plasma/Applet \
  --show dev.cosmix.plasmoid
QT_LOGGING_RULES='qt.qml.import.debug=true' \
  plasmawindowed dev.cosmix.plasmoid
```

`plasmawindowed` is a visual smoke only: process liveness and stderr silence are
not success signals because Plasma renders some QML component errors inside the
window. Automated validation passes only when the staged backend probe exits
zero, `kpackagetool6` resolves the package, opening the popup triggers one trayd
refresh, the COS tab receives a revision-consistent snapshot, and selecting Bus
opens one trayd lease which closes when the tab or popup closes. Pause ignores
traffic batches and Resume installs the newest bounded `GetBusSnapshot`.
Selecting MIX installs one `GetMixSnapshot`; create opens the authority-created
template via the default editor; run output arrives without polling; stop,
trash, restore and confirmed permanent delete operate by opaque identity only.
The SSH tab installs the latest `GetSshSnapshot` on open and `SshChanged`,
connects and probes by opaque host identity, and keeps recoverable trash visible.
The only runtime timer is the five-minute Bus lease keepalive; discovery and
stream updates are driven by trayd signals and explicit user actions. MIX has no
timer, and SSH has no visibility lease or timer.

On a live Plasma workstation, exercise notification-area adoption with an
isolated containment configuration:

```sh
tray_probe_config="$(mktemp -d /tmp/cosmix-systemtray-probe.XXXXXX)"
XDG_CONFIG_HOME="$tray_probe_config" \
XDG_DATA_DIRS="$stage_root/usr/local/share:/usr/local/share:/usr/share" \
  timeout --signal=TERM 8s \
  plasmawindowed org.kde.plasma.systemtray \
  || test "$?" -eq 124
rg -q '^plugin=dev\.cosmix\.plasmoid$' \
  "$tray_probe_config/plasmawindowedrc"
rg -q '^extraItems=.*dev\.cosmix\.plasmoid' \
  "$tray_probe_config/plasmawindowedrc"
rg -q '^knownItems=.*dev\.cosmix\.plasmoid' \
  "$tray_probe_config/plasmawindowedrc"
```

The timeout is expected; the three configuration assertions are the gate.
They prove the real Plasma system-tray containment discovered and instantiated
the staged applet. This graphical check supplements, rather than replaces, the
headless staged backend/metadata probe.

## Final deployer deltas

- This package is version `0.5.0` and requires `cosmix-trayd` `0.6.0` or newer
  for the complete COS, MIX, BUS and SSH surface.
  Deploy and restart trayd before replacing the plasmoid package so the MIX
  and SSH methods and signals exist when QML first loads.
- The ledger above is final and remains 19 files under one package root. There
  are no new units, D-Bus activation files, executable installs or paths outside
  that root for the plasmoid lane.
- Treat a manifest entry with `kind="plasmoid"` as this CMake/ECM build-stage-
  verify flow, not as a Cargo slug. Do not add the project to the desktop Cargo
  workspace.
- Do not create `~/.local/mix` during deployment. Trayd creates the private
  operator-facing store at startup.
- The package-private module names and locations are unchanged:
  `CosmixBackend/libcosmixplasmoidbackend.so` and
  `CosmixBackend/libcosmixplasmoidbackendplugin.so`. A staged-ledger mismatch is
  a hard failure.
